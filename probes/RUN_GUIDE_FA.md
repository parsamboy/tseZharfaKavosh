# راهنمای نصب برنامهٔ فیلتر — «کد تمیز» (G-32/G-33 بسته، E-081)

**فایل نصب:** `INSTALL_ME.js` (ریشهٔ مخزن — تنها فایلی در این مخزن که برای مرورگر است)
**هدف:** ثبت برنامهٔ خودمحتوی (۵۱٬۷۱۹ بایت) در تکست‌اریای فیلتر سایت تا زنده بماند و بعد از
بارگذاری مجدد هم کار کند، و نمایش پنل UX برای تغییر متغیرها.
**زمان اجرا:** یک پیست، چند ثانیه.
**تضمین‌ها:** قبل از هر نوشتن، دروازهٔ ایمنی کار می‌کند — کل بدنه از `PrepareFilterCode` خودِ
سایت عبور می‌کند و بایت‌به‌بایت مقایسه می‌شود. اگر یک بایت هم تغییر کند، **هیچ‌چیز ثبت نمی‌شود**.

---

## گام‌به‌گام

### ۱) باز کردن صفحهٔ درست
```
https://old.tsetmc.com/Loader.aspx?ParTree=15131F
```
صبر کنید صفحه **کاملاً** لود شود — جدول نمادها و نوار ابزار دیده شود.

### ۲) باز کردن Console
`F12` → تب **Console**. تگ: `[کنسول]`

### ۳) پیست فایل
**کل** محتوای `INSTALL_ME.js` را کپی و در Console پیست کنید و Enter بزنید.
**هیچ چیز دیگری لازم نیست** — موتور، مدل‌ها، لایهٔ تنظیمات و جستجوی هر ردیف همه داخل همین فایل هستند.

### ۴) خواندن نتیجه
نصب‌کننده یک خط `INSTALL_JSON {...}` و چند خط خلاصه چاپ می‌کند:
- `status: "installed"` یعنی همه‌چیز درست شد.
- `cfgHash` هش پیکربندی است؛ با هر تغییر در پنل عوض می‌شود و **این چیزی است که ثابت می‌کند تغییر اثر کرده**.
- اگر `status: "refused-the-site-would-rewrite-the-body"` دیدید، سایت بدنه را بازنویسی می‌کرد و
  نصب‌کننده عمداً هیچ‌چیز ننوشته — همان متن را بفرستید.
- اگر `status: "editor-unavailable"` دیدید، دیالوگ فیلتر را **با دست** باز کنید و دوباره پیست کنید.

### ۵) استفاده از پنل UX
پنل **پایین‌چپ** دیده‌بانی بازار ظاهر می‌شود (RTL) و برای **هر ۱۶ متغیر** یک کنترل دارد.
- یک اسلایدر را حرکت دهید و **«ذخیره»** را بزنید.
- برنامه در tick بعدی خودش پروجکشن را دوباره منتشر می‌کند و ردیف‌ها از نو داوری می‌شوند.
- `cfgHash` تغییر می‌کند — اگر تغییر نکرد، تغییر اثر نکرده.

**دلیل اینکه نیازی به پیست دوباره نیست:** برنامه از داخل کد هر ردیف tick خودش را دوباره
مسلح می‌کند و وقتی `configHash` عوض شود دوباره منتشر می‌کند. به همین دلیل نصب‌کننده **عمداً**
tick را غیرفعال نمی‌کند.

## بازگرداندن به حالت عادی

در Console:
```js
// ۱) پاک کردن کد از ادیتور فیلتر
mw.QueryWindowEditFilter();
document.getElementById('InputFilterCode').value = '';
document.getElementById('InputFilterCode').dispatchEvent(new Event('input', {bubbles:true}));
document.getElementById('InputFilterCode').dispatchEvent(new Event('change', {bubbles:true}));
document.getElementById('InputFilterName').value = '';
mw.QueryWindowSaveFilter();

// ۲) پاک کردن تنظیمات ذخیره‌شده
localStorage.removeItem('tseFunnelSettings.v1');

// ۳) رندر مجدد
mw.RenderData();
```
(پنل UX را هم `__FUNNEL_SETTINGS_CLEANUP()` حذف می‌کند.)

## چه چیزی در اجراهای زنده ثابت شده است

| اجرا | پیکربندی | نتیجه |
|---|---|---|
| E-077 | پیش‌فرض `fs1-df750af0` | بوت شد، ۲۱۸۶ ردیف، `hide 4 / keep 434 / failOpen 1748`، کراس‌چک ۲۱۸۶/۲۱۸۶ |
| E-078 | پیش‌فرض | `textarea-unavailable` — صفحه آماده نبود، نصب‌کننده درست رد کرد و هیچ‌چیز ننوشت |
| E-079 | پیش‌فرض | تکرار مستقل E-077 |
| E-080 | `ivMax: 1.0` → `fs1-f52463a4` | **`hide 4 → 100`**، `keep 434 → 338`، failOpen بدون تغییر |

**هزینهٔ هر ردیف روی صفحه:** ۳٫۶۱ / ۳٫۹۳۶ / ۳٫۷۲۹ میکروثانیه — در مقابل بودجهٔ ۱۳–۱۶ میکروثانیه.

**دروازهٔ ایمنی:** در هر چهار اجرا، `PrepareFilterCode` سایت کل ۵۱٬۷۱۹ بایت را
**بایت‌به‌بایت بدون تغییر** برگرداند (fnv1a `036ebf14` در دو طرف، `firstDiffAt=-1`). این همان
چیزی است که ۵۸ قاعدهٔ ثبت‌نشدهٔ سایت را بی‌خطر می‌کند.

## تفاوت `INSTALL_ME.js` با `RUN_ME.js`

| | `INSTALL_ME.js` | `RUN_ME.js` |
|---|---|---|
| هدف | **نصب** برنامه و نمایش UX | **اندازه‌گیری** و تأیید |
| بعد از اجرا | برنامه در اسلات و mirror **می‌ماند** | همه‌چیز **برمی‌گردد** |
| tick | **فعال می‌ماند** (پنل به آن نیاز دارد) | غیرفعال می‌شود (تا شمارش کور نشود) |
| Proxy شمارش | ندارد | دارد |
| چه وقت | وقتی می‌خواهید برنامه زنده شود | وقتی می‌خواهید بدانید درست کار می‌کند |

هر دو در ریشهٔ مخزن هستند و هر دو **یک پیست** هستند.
